# P02d2: Tooltip・Select・メニューのアクセスキー

行 P02d2（設計書 §13.1「Tooltip・Select・メニューのアクセスキー」）を、3 つの PR に分けて入れる。Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、プロセスを 1 つのコアに固定して（`start /b /wait /affinity 4 /high`）測った。比べる main は、各 PR の merge-base を `.dev/` の worktree で publish した。main と PR は、A・B・B・A の順を 2 回繰り返して流した。値は各回の中央値（p50）の範囲である。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe tooltip"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe frames --tree"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe input"
```

## 1 つ目の PR: Tooltip（Issue #563）

main は b596330（#560 のマージ）。`tooltip` の場面は、Todo のサンプル（200 項目）の上の 100 × 30 の箱に、1 行の文字の Tooltip を付ける。窓は 420 × 360 で、文字は DirectWrite でラスタライズし、GPU には送らない。待ち時間を 0 にしてタイマーを使わず、箱へのポインタの移動で、同じフレームに Tooltip を出す。

| `tooltip` の値 | この PR（4 回の範囲） |
| --- | --- |
| 出すフレーム（箱への移動から、フレームの終わりまで） | 40.6〜44.7 µs |
| 出ている間に、箱の中でポインタを動かすフレーム | 13.5〜15.3 µs |
| 動かすフレームの割り当て（1,000 フレーム） | 0 バイト |

- 出すフレームは、Tooltip の中身を作り、新しい文字の葉を 1 つシェーピングして測り、ポップアップのリストを作る。根の並びが変わるので、主のリストも作り直す（設計書 §7.3「表示リスト」）
- 動かすフレームは、何も変えない。値の大半は、Todo の 200 行が書いた主のリストのヒット領域を、ポインタの移動ごとに試す時間と推定する（未確認）。`input` の場面の、小さな木の上の移動は 0.16〜0.19 µs である
- 最初の版の場面は、動かすフレームの割り当てを 1,000 フレームあたり 48 バイトと出した。各フレームの入力とフレームの段を 1 つずつ数えると、どれも 0 だった。48 バイトは、戻り値の組 `(Median(times), …)` が、数える区間の中で配列を並べ替えたためで、`Array.Sort` が初回に作る比較の部品の分である。中央値を区間の前に求める形に直した

| Tooltip の無い経路の値 | main | この PR |
| --- | --- | --- |
| `frames --tree` の CPU の 1 フレーム | 0.629〜0.652 ms | 0.634〜0.651 ms |
| `frames --tree` の描画の段 | 0.322〜0.336 ms | 0.324〜0.336 ms |
| キー 1 つの配送（深さ 50） | 1.81〜1.96 µs | 1.77〜2.45 µs |
| Tab（10,101 ノード） | 164.5〜170.0 µs | 159.6〜173.3 µs |
| ホイール 1 つの配送 | 0.10〜0.12 µs | 0.10〜0.11 µs |
| 選べる領域のコピー（1,000 葉） | 35.0〜39.3 µs | 35.0〜39.3 µs |

- この PR が Tooltip の無い経路に足したのは、ポップアップを開くときに一時のポップアップかを見る分岐だけで、フレームごとの経路には何も足していない
- `frames --tree` の最初の組は、main の 2 回だけが、描画と Present の段が 10 倍ほど遅い状態で走った（描画 0.34〜0.41 ms と、ほかの回の 0.022〜0.029 ms）。この PR の 4 回は速い状態だった。同じ順でもう一度流すと、8 回とも遅い状態で走り、表の値はその組のものである。どちらの状態になるかは、機械の状態によると推定する（未確認）
- `input` の最初の組では、選べる領域のコピーの main の範囲が 35.5〜35.6 µs と狭く、この PR の 35.9〜39.3 µs が上に出た。この PR はその経路に触れていない。同じ順でもう一度流すと、両方とも 35.0〜39.3 µs だった。表の `input` の値は、すべて 2 回目の組のものである

## 3 つ目の PR: メニューのアクセスキー（Issue #568）

main は d97f515（#566 のマージ）。この PR は、アクセスキーの無い経路に 3 つを足した: キーの Down で Alt かを見る分岐（`WindowInput`）、ポインタの押下で下線を隠すかを見る分岐（`UiTree.HideAccessKeyCues`、2 つの値を読むだけ）、メニューのパネルのキーで文字か数字かを見る分岐（`Rune.IsLetterOrDigit`）。`menu` の場面の項目はアクセスキーを持たないので、Down とポインタのフレームは、この最後の分岐を通って、文字の探索には入らない。

| アクセスキーの無い経路の値 | main | この PR |
| --- | --- | --- |
| `frames --tree` の CPU の 1 フレーム | 0.106〜0.152 ms | 0.114〜0.156 ms |
| `frames --tree` の描画の段 | 0.022〜0.033 ms | 0.025〜0.036 ms |
| キー 1 つの配送（深さ 50） | 1.76〜1.90 µs | 1.74〜1.94 µs |
| キー 1 つの配送（深さ 1） | 0.053〜0.059 µs | 0.053〜0.059 µs |
| クリック（押下と離す） | 0.34〜0.37 µs | 0.34〜0.36 µs |
| Tab（10,101 ノード） | 156.4〜171.2 µs | 158.6〜169.6 µs |
| `menu` の開いたまま Down で移るフレーム | 4.6〜4.7 µs | 4.1〜4.6 µs |
| `menu` の開いたままポインタで移るフレーム | 4.7〜4.9 µs | 4.4〜4.8 µs |
| `menu` の移るフレームの割り当て（1,000 フレーム） | 0 バイト | 0 バイト |

- どの値も main と範囲が重なった。PR の側が下に出た値が 2 つある（スコープの中のホバーの変更と深さ 1 の移動）が、どちらもこの PR が触れていない経路である
- `frames --tree` は、8 回とも同じ速い状態で走った
