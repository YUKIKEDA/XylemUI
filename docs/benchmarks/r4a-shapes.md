# R4a: 角丸の矩形、ボーダー、塗り、影

表示リストに、角丸の矩形（角ごとの半径）とボーダー（辺ごとの幅）、塗り（単色・線形・放射・円錐のグラデーション）、角丸の矩形の影を足した（ロードマップの行 R4、Issue #246、設計書 §5.0「描く語彙とオフスクリーンの層」「形・塗り・影の API」）。その正しさと費用を確かめた。どれも Windows 11 26300、Intel Core i5-13400F、主モニタは 125 % で、時間は NativeAOT の Release で測った。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
<dir>/XylemUI.E2E.exe shapes                  # 比べの場面。benchmarks/compare/shapes.html をブラウザで並べて開く
<dir>/XylemUI.E2E.exe frames 2400             # 今の場面（矩形 1,000 個と文字 1 行）
<dir>/XylemUI.E2E.exe frames 2400 --shapes    # 矩形を、影の上の、グラデーションとボーダーの角丸にした場面
<dir>/XylemUI.E2E.exe fill-rect 1.25          # 矩形 1,000 個を書くだけ、1 個
<dir>/XylemUI.E2E.exe draw-text               # 定常状態の DrawText、1 グリフ
```

## 正しさ（WARP、`ShapeRenderTests`）

WARP で描いた画素を読み戻し、CPU の基準（`ShapeReference`）を背景の上に重ねた値と比べた。

| 場合 | 許した差 | 最大の差 |
| --- | --- | --- |
| 角ごとに違う半径の角丸の矩形と、辺ごとに違う幅のボーダー | 1 | 1 以内 |
| 塗りの上の半透明のボーダー | 1 | 1 以内 |
| 辺より大きい半径（CSS の縮め方） | 1 | 1 以内 |
| 線形（0・45・90 度）、放射、円錐、Oklab、硬い境目 | 2 | 1 |
| 透明へのフェード | 2 | 2 |
| 外側の影（ずらし 6, 4、ぼかし 16、広げ 3） | 1 | 1 |
| 内側の影（ずらし 4, 6、ぼかし 12、広げ 2） | 1 | 1 |

- **グラデーションの許容:** 2 にした。ディザが 8 ビットの 1 段まで足し、丸めがもう 1 段足すためである。透明へのフェードだけ、半透明の所にディザが乗って 2 になった
- **影の基準:** シェーダの式の写しにしていない。角丸の矩形の各行の x の幅で正確に積分し、y 方向は 0.02 画素ごとに数値で積分した。シェーダは、erf を多項式で近似し、y 方向を 4 点で取る（GPUI の式）。それでも差は 1 以内だった
- **外側の影の切り抜き:** 基準は形の内側で影を 0 にしていて、そこでも 1 以内なので、形の内側に影は描かれていない
- **定常状態:** 形・グラデーション・影の 50 組のフレーム（`SteadyState_ShapesAndShadows_AllocateNothing`）は、アロケーション 0 で、表示リストも伸びなかった

## CSS と並べる（目での確認の前に）

`benchmarks/compare/shapes.html` を Edge の headless で撮った（1.25 倍、600 × 480）。`XylemUI.E2E shapes` を `text-capture` で撮った絵と、領域ごとに比べた（チャネルの差の最大）。

| 領域 | 中央値 | p95 | 最大 |
| --- | --- | --- | --- |
| 角丸とボーダー | 0 | 0 | 223 |
| 外側の影のカード | 0 | 2 | 52 |
| 内側の影 | 0 | 2 | 55 |
| 線形 45 度 | 1 | 2 | 210 |
| 放射 | 2 | 3 | 212 |
| 円錐 | 1 | 5 | 212 |
| Oklab | 1 | 2 | 210 |
| 透明へのフェード | 1 | 2 | 210 |
| 硬い境目 | 0 | 1 | 212 |
| 半透明のカードと影 | 0 | 2 | 59 |
| 塗りの上の半透明のボーダー | 0 | 0 | 195 |
| 高さの半分を超える半径 | 0 | 0 | 211 |

- **最大の差:** どれも、箱の縁が 1 画素ずれている所である。2 列目の箱の左端は 210 px で、125 % では 262.5 画素になる。XylemUI は最も近い偶数へ丸めて 262 画素から描き、Edge は 263 画素から描いた。GPUI もゼロから遠い方へ丸める。W1 の丸めの問題として、行 W2（Issue #247）に分けた。4 段目の箱も、下端の 562.5 画素と右端の 212.5・437.5 画素で同じずれが出た
- **ボーダーと塗り:** ボーダーは塗りの上に重なる。半透明の青のボーダーの中の画素は、XylemUI も Edge も (128, 48, 128) で、下の赤の塗りが透けている
- **半径の縮め方:** 一辺の 2 つの半径の和が辺を超えるとき、CSS の 5.5 節のとおり、すべての半径を同じ比で縮める。高さ 50 の箱に半径 40 を付けると、どちらも半径 25 の両端が丸い形になった
- **形の違い:** 辺ごとに幅の違うボーダーの内側の角を、CSS は楕円で描く。XylemUI は、大きい方の幅を引いた円で描く
- **ボーダーの下のグラデーション:** XylemUI はグラデーションを箱の外側の縁から始める。CSS はボーダーの内側の縁から始める（`background-origin` の既定が `padding-box`）。比べの場面には、ボーダーとグラデーションを両方持つ形を置いていない

## 費用（main 91f9eb9 と交互に、5 回ずつ、中央値）

インスタンスは 28 バイトから 32 バイトになった（形の行の番号を足した）。レビューの修正の後に測り直した。

| | main | R4a |
| --- | --- | --- |
| `frames` の表示リストの段 | 29.3〜30.3 µs | 29.8〜31.1 µs |
| `frames` の Draw の段 | 29.6〜30.8 µs | 30.1〜31.7 µs |
| `frames` の GPU | 110.6〜112.6 µs | 113.7〜114.7 µs |
| `fill-rect`（1 個） | 7.56〜8.05 ns | 7.42〜7.67 ns |
| `draw-text`（1 グリフ） | 45.9〜47.5 ns | 48.2〜48.6 ns |

- **今の場面:** CPU の段は範囲が重なる。GPU は 2〜3 µs 増えた。今の場面で変わったのは、インスタンスが 4 バイト大きくなったことと、画素シェーダに形かどうかの分岐が 1 つ入ったことだけである
- **`draw-text`:** レビューの前の版（0c01ed1）では main と同じだった（同じ日に交互に 5 回ずつ、中央値 46.5 と 46.6 ns）。レビューの修正は `DrawText` を変えていない。2 つの版の `DrawText` の機械語を `dumpbin /disasm` で比べると、351 行の命令がすべて同じで、置き場所が 0x80 バイト後ろへずれただけだった。この差は、同じ命令列の配置の違いである
- **形の場面（`frames --shapes`、影 1,000 個とグラデーションの角丸 1,000 個）:** 表示リストの段は 69.0〜69.7 µs、Draw の段は 77.9〜80.3 µs、GPU は 1,102.8 µs だった（3 回）
- **GPU の内訳:** レビューの前の版で、片方だけを描く一時的な版を作って測った（1,200 フレーム、3 回）
  - 影だけ: 722〜723 µs
  - 塗りだけ（グラデーションとボーダー）: 320 µs
  - 影と単色の塗り: 1,030〜1,031 µs（影とグラデーションでは 1,046〜1,048 µs なので、グラデーションの分は約 18 µs）
  - 影は 1 つ約 0.6 µs だった。影の四角形はぼかしの裾のために 3σ ずつ広げてあり（この場面では σ = 6 / 2 × 1.25 = 3.75 画素で、16 × 1.25 = 20 画素の箱が 20 + 2 × 11.25 = 42.5 画素四方になる）、その 1 画素ごとに y 方向 4 点で erf を求める

## 角丸の距離の場の選び方（PR #248 のレビュー）

CSS の比で縮めた後の半径は、短い辺の半分を超えることがある。その形を正しく描く式を、レビューの前の版（0c01ed1、各半径を短い辺の半分で切る GPUI の式）と交互に測った。どれも `frames --shapes` の GPU の中央値で、2〜3 回とも同じ値だった。

| 式 | GPU |
| --- | --- |
| レビューの前の版（半径を半分で切る） | 1,047.6〜1,048.6 µs |
| 半径を切らない GPUI の式（比べのための一時的な版。半径が半分を超える形は描けない） | 1,034.2〜1,035.3 µs |
| 画素を含む角を `if` で選ぶ | 1,152.0 µs |
| どの半径も半分以下なら GPUI の式、そうでなければ一般の式（形ごとに同じ側へ進む分岐。`[branch]` をつけても 1,119.2 µs） | 1,112.1 µs |
| 同じ分岐で、一般の式の側を空にした一時的な版 | 1,154.0 µs |
| 4 つの角の円弧の最大（分岐なし） | 1,138.7 µs |
| 対角の 2 つの角の円弧の最大（分岐なし、採った式） | 1,102.8 µs |
| 塗りだけ採った式、影の切り抜きは半径を半分で切る式 | 1,072.1〜1,074.2 µs |
| 影の種類で分岐して、内側の影だけ採った式で切り抜く | 1,205.2 µs |

- **分岐:** 一般の式の側を空にしても遅いので、遅いのは一般の式ではなく分岐そのものである。距離の場は 1 画素で 3 回（形の外側、ボーダーの内側、影の切り抜き）呼ばれる
- **採った式:** 同じ辺の 2 つの角の正方形は重ならないので、画素を含みうるのは対角の 2 つの角までになる。円弧の距離を 2 回求め、選ぶのは分岐でなく条件の値で行う。レビューの前の版より 5 % 遅い
- **影の切り抜きを安い式にする案は採らなかった:** 30 µs 速いが、内側の影を、塗りより大きい形で切り抜くことになる。半径が半分を超える角で、内側の影が形の外にはみ出す
- **今の場面（矩形だけ）:** どの式でも GPU は 112.6〜117.8 µs の中にあり、採った式は 113.7〜114.7 µs（レビューの前の版は 112.6〜114.7 µs）だった
