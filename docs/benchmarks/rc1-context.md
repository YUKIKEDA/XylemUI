# RC1: Reactive Context の値の置き場所

値の置き場所の 3 案を測った（ロードマップの行 RC1、Issue #838、設計書 §2.13「値の置き場所は、測ってから決める」）。Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で測った。

## 3 案

- **(a)** Scope ごとに、そこで置いた値のリストの頭を持つ。引く時は親へ 1 つずつ上がり、各 Scope のリストを見る
- **(b)** Scope には「置いた」の印だけを持ち、リストの頭は Scope ごとの別の表（`Dictionary`）に置く。引く時は親へ上がり、印のある Scope でだけ表を見る
- **(c)** Scope ごとに、親から受け継いだリストの頭を持つ。値を置いた Scope は、その前に自分の値をつなぐ。引く時は親をたどらず、リストを頭から見る。Flutter と SolidJS のように表を写すのではなく、リストを共有するので、Scope を作る時に写すのは頭 1 つである

どの案も、今の Scope が無い所で作った Effect を見分ける印（`Unowned`）を持つ。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -p:Rc1Store=A -o <dir>   # B、C も同じ
cmd /c start "" /affinity 4 /high /wait /b <dir>\XylemUI.E2E.exe context
cmd /c start "" /affinity 4 /high /wait /b <dir>\XylemUI.E2E.exe todo                  # RC1_WRAP=1 で、行を Provide で包む
```

- **順:** `context` は A・B・C・C・B・A を 2 巡（案ごとに 4 回）。`todo` は main・A・B・C・C・B・A・main を 2 巡、行を包んだ場合は A・B・C・C・B・A を 2 巡
- **負荷:** ほかのプロジェクトのプロセスが動いていた。各回の直前の CPU の負荷は 0.3〜49.5 %、直後は 1.9〜50.6 % だった。負荷が下がるのを待たずに測った（オーナーの指示）
- **値:** 4 回の中央値。かっこの中は最小〜最大

## 採った形: (c) で、リストの頭を 4 バイトの番号にする（Issue #838 でオーナーが決定）

(c) のリストの頭を、世代つきのハンドル（16 バイト）から、世代のない番号（4 バイト）に替えた。値の項目は、それを置いた Scope が破棄される時に解放され、その下の Scope はそれより先に破棄されるので、古い番号を引く Scope は残らない。

main（`bf75524`）と交互に測った。`context` は main・新・新・main を 3 巡（6 回ずつ）、`todo` は同じ順を 2 巡（4 回ずつ）と、行を包んだ場合を 4 回。各回の直前の CPU の負荷は 32.7〜59.1 % だった。
