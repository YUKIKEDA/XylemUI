# DD1: D&D と明示のポインタキャプチャ

行 DD1（設計書 §7「ドラッグ＆ドロップ」）を 2 つの PR に分けて入れる。Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、プロセスを 1 つのコアに固定して（`start /b /wait /affinity 4 /high`）測った。比べる main は、各 PR の merge-base を `.dev/` の worktree で publish した。main と PR は、A・B・B・A の順を 2 回繰り返して流した。値は各回の中央値（p50）の範囲である。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe dragdrop"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe frames --tree"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe input"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe menu"
```

## 1 つ目の PR: アプリ内の D&D と明示のキャプチャ（Issue #598）

main は 9775362。`dragdrop` の場面は、Todo のサンプル（200 項目）の行を、ドラッグ元（像あり）とドロップ先（`DragOver` の見た目あり）にしたものである。窓は 420 × 360 で、文字は DirectWrite でラスタライズし、GPU には送らない。1 行目からドラッグを始め、2 行目と 3 行目の上へ交互にポインタを動かす。1 回の移動ごとに、ヒットテスト、前のドロップ先の Leave と新しいドロップ先の Enter、`DragOver` の付け外し、像の置き直しが起き、そのフレームを描く。値は、移動とそのフレームの合計である。

| `dragdrop` の値 | この PR（4 回の範囲） |
| --- | --- |
| ドロップ先が変わる移動のフレーム | 270〜307 µs |
| 移動のフレームの割り当て（1,000 フレーム） | 0 バイト |
| 移動のフレームで主のリストを作り直した回数（1,000 フレーム） | 1,000 |

- 移動のたびに、主のリストを作り直す。行は主の木にあり、`DragOver` の見た目が変わると、主のリストを書き直すからである（メニューバーの項目の移動と同じ、`docs/benchmarks/p02d3.md`）。値の大半は、Todo の 200 行の主のリストを作り直す時間である。像は自分の描画ルートにあり、置き直すと、像のリストだけを作り直す
- 8 回とも、`frames --tree` の描画の段が遅い状態（0.37〜0.43 ms）で走った。同じ状態どうしなので、そのまま比べた

| --- | --- | --- |
| `frames --tree` の CPU の 1 フレーム | 0.722〜0.873 ms | 0.711〜0.790 ms |
| `frames --tree` の描画の段 | 0.372〜0.427 ms | 0.367〜0.403 ms |
| ポインタの移動の配送（深さ 50） | 4.40〜5.36 µs | 4.37〜5.32 µs |
| クリックの配送 | 0.335〜0.379 µs | 0.340〜0.371 µs |

- この PR がドラッグの無い経路に足したのは、ポインタの移動ごとの「ドラッグが待っているか、動いているか」を見る分岐、Down・Up・CaptureLost で待っているドラッグを外す分岐、キーごとの「ドラッグが動いているか」の分岐、フレームごとの自動スクロールの判定（ドラッグが無ければすぐ戻る）である
- `input` は 3 組流した。1 組目（上の表の値）では、ポインタの移動（深さ 1）だけ、この PR の 4 回が main の 4 回より下に出た（main 0.176〜0.276 µs、この PR 0.164〜0.176 µs）。逆の順で流した 2 組目では重なった（main 0.149〜0.175 µs、この PR 0.152〜0.166 µs）
- 2 組目では、選べる領域の 1,000 葉を描くフレームの描画の段が、この PR の方が上に出た（main 435.6〜442.1 µs、この PR 444.9〜464.1 µs）。1 組目でも、この PR の最小値は main の最小値より上だった（main 436.8〜618.5 µs、この PR 451.3〜494.8 µs）。この PR は描画の経路に、疑似状態の見た目の解決の分岐（`Open` と `DragOver` をまとめた `RareStyles`）と、フレームごとの自動スクロールの判定と像の置き場所の分岐を足し、選べる領域には Cancel のハンドラを足した
- そこで `open-ends` の規則のとおり、変更の一部だけを main の形に戻した写しを 2 つ作り、main とこの PR と並べて、順を入れ替えて 4 回ずつ流した（3 組目）。写し A は選べる領域の Cancel のハンドラを main の形に戻し、写し B はフレームに足した 2 つの分岐を外した

| 選べる領域の 1,000 葉のフレームの描画の段（3 組目、4 回の範囲） | |
| --- | --- |
| main | 475.9〜592.8 µs |
| この PR | 430.4〜742.4 µs |
| 写し A（選べる領域の Cancel を戻した） | 435.9〜490.5 µs |
| 写し B（フレームの 2 つの分岐を外した） | 442.3〜493.0 µs |

- 3 組目では 4 つとも重なり、この PR の最小値は main の最小値より下に出た。写しはどちらも、この PR と同じ範囲にある。3 組で向きがそろわず、どの変更にも差がついてこないので、`bench` の規則のとおり、ばらつきの中として差には数えない
