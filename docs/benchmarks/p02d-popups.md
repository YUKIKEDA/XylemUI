# P02d: ポップアップ

ポップアップを、2 つの PR に分けて入れる（ロードマップの行 P02d、設計書 §7.2・§7.3）。前半は 1 つ目の PR（Core、Issue #551）で、後半の「2 つ目の PR」の節は 2 つ目の PR（Primitives、Issue #555）で測った。Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、プロセスを 1 つのコアに固定して（`start /b /wait /affinity 4 /high`）測った。比べた main は設計 PR のマージ（#548、c6d105d）で、main とこの PR を交互に 4 回ずつ流した。値は各回の中央値（p50）の、4 回の範囲である。開いたポップアップの費用（10 項目のメニューを開く、開いたままのキーとポインタ）は、2 つ目の PR で測った。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe frames --tree"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe input"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe todo"
```

NativeAOT のリンクは `vswhere.exe` を PATH から探す。Git Bash から呼ぶと見つからずに失敗するので、`C:\Program Files (x86)\Microsoft Visual Studio\Installer` を PATH に足す。

## ポップアップを開いていないフレーム

この PR は、ポップアップが無いときも通る経路を 4 つ変えた: 描画の段（根ごとのリスト、`IRenderTarget.Draw` がリストの並びを受け取る、ヒット領域を書かない印の確かめ）、キーの経路の親のたどり（ポップアップの根から開いた側へ続く）、ポインタの当たり（手前のポップアップから試す）、ハンドラに渡す位置のリストの引き方（`ListOf`）。

| 場面の値 | main | この PR |
| --- | --- | --- |
| `frames --tree` の CPU の 1 フレーム | 0.61〜0.65 ms | 0.61〜0.64 ms |
| `frames --tree` の描画の段 | 0.31〜0.34 ms | 0.31〜0.34 ms |
| キー 1 つの配送（深さ 50） | 1.67〜2.53 µs | 1.69〜1.74 µs |
| ホイール 1 つの配送 | 0.10〜0.10 µs | 0.10〜0.11 µs |
| タッチのドラッグの 1 移動 | 0.09〜0.10 µs | 0.09〜0.10 µs |
| 欄の点滅の 1 フレーム | 38.3〜42.8 µs | 38.4〜39.3 µs |
| 1,000 葉の全選択 | 470.7〜512.7 µs | 464.4〜477.2 µs |
| Todo の追加の変更の段 | 39.7〜40.3 µs | 39.1〜46.9 µs |
| Todo の追加の描画の段 | 893.8〜944.7 µs | 879.4〜1,072.1 µs |

- 4 回とも main のどの回よりも上になったのは、ホイール 1 つの配送だけだった（0.10 µs と 0.10〜0.11 µs）。差は出力の桁の 0.01 µs で、この PR がホイールの経路に足したのは、当たりを試す前の「開いたポップアップがあるか」の確かめ 1 つである
- 最初の版は、キーの配送が 4 回とも main より上だった（深さ 50 で、main の 1.69〜1.76 µs に対して 1.97〜2.01 µs）。キーを直した 2 つ目の版は、描画の段が 4 回とも main より上だった（1,000 葉の全選択の描画で、main の 427.2〜437.3 µs に対して 438.4〜446.4 µs、ノード 1 つ約 10 ns）。どちらも、main を毎回流し直して比べた。キーは、経路の親をたどる関数を、ポップアップが無いときに親を返すだけの小さな関数にして、その場に展開させた。描画の段は、ノードごとの関数の引数に足した「ヒット領域を書かない」の印をやめ、印のあるノードの中にいる間だけ数えるフィールドにした。上の表は、直した後の値である
- Todo の追加の変更の段と描画の段の上の端（46.9 µs、1,072.1 µs）は、この PR の 3 回目だけで、ほかの 3 回は 39.1〜39.9 µs と 879.4〜920.7 µs だった。同じ回の切り替えの描画の段も 996.3 µs と長く（ほかの回は 882.9〜896.4 µs）、その回の揺れとみる。main の 4 回にも、切り替えの描画の段が 1,300.7 µs になった回がある

## 2 つ目の PR: メニュー

2 つ目の PR は、#552 のマージ（95c4112）を main として、同じ形で 4 回ずつ交互に流した。`menu` の場面を足した（`XylemUI.E2E.exe menu`）: Todo のサンプル（200 項目）の上の 100 × 30 の箱から、文字の項目 10 個のメニューを開く。項目はホバーとフォーカスの見た目を持つ。窓は 420 × 360 で、文字は DirectWrite でラスタライズし、GPU には送らない。

| `menu` の値 | この PR（4 回の範囲） |
| --- | --- |
| 開くフレームの変更の段（signal を書いてから、ポップアップの部品ができるまで） | 21.3〜22.2 µs |
| 開くフレームのレイアウトの段 | 63.5〜65.0 µs |
| 開くフレームの残り（主のリストとポップアップのリストを作る） | 5.4〜5.5 µs |
| 開いたまま Down で次の項目へ移るフレーム（入力からフレームの終わりまで） | 4.3〜4.7 µs |
| 開いたままポインタを次の項目へ動かすフレーム | 4.3〜4.8 µs |
| 移るフレームの割り当て（1,000 フレーム） | 0 バイト（Down とポインタの両方） |
| 移るフレームで主のリストを作り直した回数（1,000 フレーム） | 0（Down とポインタの両方） |

- 開くフレームのレイアウトの段は、ポップアップの根だけを測る（主の木にはレイアウトの要求が無い）。開くたびに作る 10 個の文字の葉を、初めてシェーピングして測るので、1 項目あたり約 6.4 µs になる。Todo の追加（1 行を足す）のレイアウトの段が 100 µs 前後なのと同じく、新しい葉の測りが大半を占める
- 開くフレームは、根の並びが変わったので主のリストも作り直す（設計書 §7.3「表示リスト」）。Todo のスクロールの箱が見える行だけを描き、グリフはアトラスにあるので、残りの段は 5.5 µs ほどで済む
- 移るフレームは、フォーカスとホバーの見た目が変わった項目を含むポップアップのリストだけを作り直す。場面は、各入力でフォーカスが別の項目に移ったことを確かめてから測る

| ポップアップを開いていない経路の値 | main | この PR |
| --- | --- | --- |
| `frames --tree` の CPU の 1 フレーム | 0.65〜0.75 ms | 0.65〜0.75 ms |
| `frames --tree` の描画の段 | 0.34〜0.39 ms | 0.34〜0.38 ms |
| キー 1 つの配送（深さ 50） | 1.74〜2.57 µs | 1.75〜1.78 µs |
| Tab（10,101 ノード） | 157.0〜170.2 µs | 158.0〜162.5 µs |
| ホイール 1 つの配送 | 0.10〜0.12 µs | 0.10〜0.11 µs |
| Todo の追加の変更の段 | 41.2〜50.6 µs | 41.6〜44.9 µs |
| Todo の追加の描画の段 | 897.0〜1,101.5 µs | 939.0〜1,031.3 µs |

- この PR は、ポップアップの無いフレームの経路に 2 つを足した: フレームの初めに、アンカーが根に付くのを待っているポップアップがあるかの確かめ（`OverlayPopupHost.HasWaiting`）と、Tab の移動を `FocusManager.Move` に移したこと。`frames`・`input`・`todo` の値は、どれも main と範囲が重なった
