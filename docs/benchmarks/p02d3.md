# P02d3: 窓全体のアクセスキー・Label・メニューバー

行 P02d3（設計書 §13.1「窓全体のアクセスキー・Label・メニューバー」）を、2 つの PR に分けて入れる。Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、プロセスを 1 つのコアに固定して（`start /b /wait /affinity 4 /high`）測った。比べる main は、各 PR の merge-base を `.dev/` の worktree で publish した。main と PR は、A・B・B・A の順を 2 回繰り返して流した。値は各回の中央値（p50）の範囲である。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe frames --tree"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe input"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe menu"
```

## 1 つ目の PR: 窓全体のアクセスキーと Label（Issue #577）

main は 82c1503（#576 のマージ）。この PR がアクセスキーの無い経路に足したのは、次の 2 つだけである。

- キーが経路を流れ終えて誰も止めなかったときに、Alt があり Control が無いかを見る分岐（`WindowInput.HandleKeyInBatch`）
- ボタンを作るときに、アクセスキーの相手として登録する 1 回の辞書の書き込み

フレームごとの経路には何も足していない。

| アクセスキーの無い経路の値 | main | この PR |
| --- | --- | --- |
| `frames --tree` の CPU の 1 フレーム（速い状態の回） | 0.124〜0.132 ms | 0.119〜0.138 ms |
| `frames --tree` の描画の段（速い状態の回） | 0.027〜0.030 ms | 0.026〜0.030 ms |
| キー 1 つの配送（深さ 1） | 0.052〜0.060 µs | 0.052〜0.060 µs |
| キー 1 つの配送（深さ 50） | 1.69〜1.88 µs | 1.70〜1.81 µs |
| キーでのボタンのクリック | 0.103〜0.114 µs | 0.103〜0.106 µs |
| Tab（10,101 ノード） | 158.0〜164.0 µs | 159.3〜163.3 µs |
| ホイール 1 つの配送 | 0.10〜0.11 µs | 0.10〜0.11 µs |
| メニューを開いたまま Down で移るフレーム（`menu`） | 4.6 µs | 4.2〜4.6 µs |
| 移るフレームの割り当て（`menu`、1,000 フレーム） | 0 バイト | 0 バイト |

- `frames --tree` は、main の 1 回目とこの PR の 7 回目だけが、描画の段が 10 倍ほど遅い状態で走った（描画 0.38 ms と、ほかの回の 0.026〜0.030 ms）。表の値は、両方の残りの 3 回である
- `input` は 2 組流した。2 組目は、1 組目と逆の B・A・A・B の順を 2 回である。表の `input` の値は 2 組目のもので、1 組目とも重なる
- 文字の欄の Control+Left（`text_field_word_move`）では、配送の部分だけが、2 組とも 4 回すべてでこの PR の方が上に出た。main は 19.0〜21.2 µs、この PR は 19.9〜22.3 µs で、差はおよそ 0.8 µs である。フレームまでの合計は、2 組目で main 58.6〜64.8 µs、この PR 59.5〜66.0 µs と重なる。このキーは、文字の欄のハンドラが止める（`TextField.cs` 583〜586 行目）ので、この PR が足した分岐まで来ない。たとえ来ても、その分岐は比較 2 つで、0.8 µs（このコアでおよそ 3,000 サイクル）にはならない。単語の境界をたどるコードも、この PR は変えていない。差は、変わっていないコードが、バイナリの中で置かれる位置が変わったためと推定する（プロファイルでは確かめていない）
