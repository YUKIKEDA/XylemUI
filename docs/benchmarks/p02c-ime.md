# P02c: IME

IME を、3 つの PR に分けて入れた（ロードマップの行 P02c、設計書 §4.7）。Core の口と変換中の文字の描き方とヘッドレスの `app.Ime`（#523）、Windows の TSF（#540）、タッチキーボード・入力の種類・計測（3 つ目の PR）。この記録は、3 つ目の PR で測った。Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、プロセスを 1 つのコアに固定して（`start /b /wait /affinity 4 /high`）測った。比べた main は 2 つ目の PR のマージ（#540、76e0852）で、main とこの PR を交互に 4 回ずつ流した。値は各回の中央値（p50）の、4 回の範囲である。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe input"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe lists"
cmd /c "start /b /wait /affinity 4 /high """" <dir>\XylemUI.E2E.exe rich-text"
```

`start` は `/b` を付けて同じコンソールで走らせる。付けないと新しいコンソールに出て、出力をファイルに取れない。

## 変換中の文字の費用

TextField の計測（P02b、`benchmarks/XylemUI.E2E/TextFieldCost.cs`）と同じ欄（複数行、400 × 300、Windows のフォントの 14 px の英語の文を 1,000 文字、約 20 行に折り返す）で、末尾で変換する。IME を持つ場面を別に作り、IME の代わりに、欄の相手を TSF と同じ順で呼ぶ（`BenchIme`）。既存の 4 つの計測の場面は、前と同じく IME を持たない。

| 操作 | 全体 | 配送 | レイアウト | 描く |
| --- | --- | --- | --- | --- |
| 変換中の文字の更新（「にほんご」と「日本語」を交互に、文節 1〜2） | 134.5〜153.7 µs | 0.8〜1.6 µs | 85.3〜96.2 µs | 47.8〜53.3 µs |
| 「日本語」の確定 | 127.5〜225.6 µs | 1.7〜5.4 µs | 85.2〜162.2 µs | 39.8〜56.7 µs |
| （比べるため）末尾に 1 文字打つ（既存） | 124.9〜205.8 µs | 0.5〜3.0 µs | 84.5〜146.0 µs | 39.0〜54.6 µs |

- **レイアウト（約 90 µs）:** 変換中の文字の更新は欄の文字を変えるので、打ち込みと同じく、葉の整形の結果を捨てて 1,000 文字を整形し直す（設計書 §3.2）。打ち込みの 1 文字とほぼ同じ時間である
- **描く段（約 50 µs）:** 変換中の文字の更新は、打ち込みより約 10 µs 長い。文節ごとに範囲を持つので、範囲で分けたグリフの並びと、文節の下線を書く分である（§4.7「変換中の文字の描き方」）
- **確定:** 確定した文字は変換中の文字と同じなので、文字は変わらず、文節の範囲が消える。レイアウトは、範囲が変わって葉を書き直すので走る
- **3 回目の幅:** この PR の 3 回目は、打ち込み（205.8 µs）も確定（225.6 µs）も、ほかの回（125〜140 µs）より長かった。同じ回のほかの場面も長く、機械の揺れとみる

## main への影響

`input`・`lists`・`rich-text` のどの値も、この PR の 4 回の範囲が main の 4 回の範囲と重なった。4 回とも main のどの回よりも上になった値は無かった。1 回だけ main のどの回よりも上になったのは、この PR の 3 回目の欄の値（1 文字打つの 205.8 µs など）で、上の節に書いたとおり、同じ回のほかの場面も長かった。

| 場面の値 | main | この PR |
| --- | --- | --- |
| 1 文字打つ（`text_field_type_1000_chars_us_p50`） | 123.1〜139.7 µs | 124.9〜205.8 µs |
| 単語の移動 | 58.5〜90.3 µs | 58.8〜65.9 µs |
| 点滅の 1 フレーム | 39.1〜43.8 µs | 38.7〜43.7 µs |
| 選択のドラッグの 1 フレーム | 41.8〜57.8 µs | 41.2〜46.4 µs |
| 1 回のクリック | 0.331〜0.380 µs | 0.336〜0.379 µs |
| キー 1 つの配送（深さ 1） | 0.051〜0.059 µs | 0.052〜0.059 µs |
| `lists` の追加のレイアウト | 2,511〜2,691 µs | 2,345〜2,526 µs |
| `rich-text` の範囲つきの描く段 | 239.5〜260.7 µs | 241.7〜270.8 µs |

押下は、押下の種類をフォーカスの管理に覚えるようになった（タッチキーボードのため）。1 回のクリック・タッチのタップの値は、main の範囲の中だった。

変換していないフレームの割り当ては 0 のまま（`TextFieldTests` の点滅のフレームと、Core の Zero-Alloc のテスト）。
