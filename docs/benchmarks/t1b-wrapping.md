# T1b: 折り返しと内容の幅

整形した文字を行に折り返す処理（Pass1）、行の境界を整形し直して並べる処理（Pass2）、内容の幅を足した（ロードマップの行 T1、Issue #292、設計書 §4.1 の 2 パスと「改行と書記素の決定」）。その正しさと費用を確かめた。どれも Windows 11 26300、Intel Core i5-13400F で、時間は NativeAOT の Release で測った。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
<dir>/XylemUI.E2E.exe segment
```

`segment` は、T1a と同じ画面 1 枚（40 行 × 80 文字以上）の文を、Windows のフォント（`DirectWriteFontProvider`）でフォントの run に分けて測る。手順は次のとおりで、どれも 20 回の平均の中央値である。

1. 16 px で 1 回整形する（`ShapingResult.Shape`。HarfBuzz と T1a の改行の候補）
2. 幅 640 px で折り返す（`Wrap`、Pass1）
3. 行を並べる（`Lay`、Pass2）
4. 幅 480 px で折り返し直す（整形の結果を使い回す）

## 正しさ（`TextWrapTests`）

テストのフォントを 1,000 px で整形するので、フォントの単位が 1 画素になる。期待値は、fontTools で読んだ hmtx と kern の値から求めた。グリフの幅は n が 610、ハイフンが 347、T が 599、空白が 224 で、カーニングはハイフンの後の T が -55 である。

- **切ると危ない印:** カーニングのかかる組の後ろのグリフ（ハイフンの後の T）に `UnsafeToBreak` が付き、カーニングの無い組（n と n）には付かない
- **行末の空白:** 行の外にはみ出し、幅に入らない（1,220 px、空白を入れると 1,444 px）
- **行より広い語:** 書記素の境界で、収まるだけ切る。1 つの書記素が行より広くても、1 つは取る
- **強制改行:** 必ず行を終え、幅に入らない
- **ソフトハイフン:**
  - 改行した行では、ハイフンのグリフになり、幅に入る（1,567 px）
  - 改行しない行では描かれず、幅は 0
  - ハイフンを足すと収まらないときは、手前の候補で改行し、緊急ブレークにならない
- **行の境界の整形のやり直し:** ハイフンの後で改行すると、ハイフンはカーニングを失い（Pass1 の 1,512 px が Pass2 で 1,567 px）、次の行の T もカーニングなしで整形される
- **Pass2 で溢れた行:** 幅 1,540 px では、Pass1 で収まった「nn-」が Pass2 で 1,567 px になる。そのため、書記素の境界で 1 回だけ切る（「nn」と「-」）。行の折り返しはやり直さない
- **内容の幅:** 最小は、改行の候補の間の最も広い並び（ソフトハイフンの並びはハイフン込み）。最大は、強制改行の間の最も広い行。どちらも行末の空白を入れない
- **割り当て:** 同じ整形の結果を、2 つの幅で交互に折り返して並べる処理は、0 バイトだった
- **ミュータント:** 5 個（行末の空白を除かない、ソフトハイフンの幅を判定に入れない、行の境界で整形し直さない、Pass2 で溢れても切らない、ソフトハイフンをハイフンに置き換えない）。どれも、狙ったテストが落ちた

## 費用（`segment`、3 回の範囲）

| 文 | 整形（1 回） | 折り返し（Pass1） | 行を並べる（Pass2） | 幅を変えて折り返し直し | 行の数 |
| --- | --- | --- | --- | --- | --- |
| 日本語 | 273.1〜276.7 µs | 18.3〜18.5 µs | 14.5〜16.1 µs | 18.5〜18.7 µs | 68 |
| 英文 | 242.0〜247.3 µs | 5.2 µs | 13.9〜14.5 µs | 4.8〜4.9 µs | 38 |
| 絵文字の混じった英文 | 501.9〜586.6 µs | 4.4〜4.5 µs | 11.8〜19.1 µs | 4.7〜4.8 µs | 32 |

- **整形:** 時間の大半を占め、文字の内容が変わったときだけ行う。T1a の改行の候補（画面 1 枚で約 70〜90 µs）を含む。絵文字の混じった文は、フォントの run が 321 個あり、run ごとに HarfBuzz を呼ぶので長い
- **折り返し:** 改行の候補の数に比例する。日本語は、ほぼすべての文字の間が候補なので、空白の後だけが候補の英文の約 3.5 倍になる
- **行を並べる:** 行ごとにグリフを写す。行の境界の整形のやり直しは、切ると危ない印のある境界と、ソフトハイフンで改行した行の末尾だけで行う
- **幅だけが変わったとき:** 折り返しと行を並べ直すだけで、日本語の画面で約 33〜35 µs である。§3.2 の 2 段のキャッシュは、行 V1a でこの形につなぐ
