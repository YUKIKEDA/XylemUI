# R4b: 線・楕円・円弧と文字の塗り

表示リストに、線・楕円の塗りと線・円の円弧の線・扇形の塗り・破線と、それらと文字へのグラデーションを足した（ロードマップの行 R4、Issue #255、設計書 §5.0「線・楕円・円弧と文字の塗りの API」）。その正しさと費用を確かめた。どれも Windows 11 26300、Intel Core i5-13400F、主モニタは 125 % で、時間は NativeAOT の Release で測った。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
<dir>/XylemUI.E2E.exe curves                  # 比べの場面。benchmarks/compare/curves.html をブラウザで並べて開く
<dir>/XylemUI.E2E.exe frames 1200             # 今の場面（矩形 1,000 個と文字 1 行）
<dir>/XylemUI.E2E.exe frames 1200 --shapes    # R4a の形の場面
<dir>/XylemUI.E2E.exe frames 1200 --curves    # 線・楕円・円弧を 1,000 個ずつと、グラデーションの文字 1,000 グリフ
<dir>/XylemUI.E2E.exe draw-text               # 定常状態の DrawText、1 グリフ
<dir>/XylemUI.E2E.exe fill-rect 1.25          # 矩形 1,000 個を書くだけ、1 個
```

## 正しさ（WARP、`CurveRenderTests`・`BrushedTextRenderTests`）

WARP で描いた画素を読み戻し、CPU の基準（`CurveReference`）を背景の上に重ねた値と比べた。基準は、シェーダの近道（近い破線だけを測ること）を使わず、すべての破線を測る。楕円は、4,096 点の中で最も近い点を三分探索で詰めた距離を使う。

| 場合 | 許した差 |
| --- | --- |
| 線の 3 つの端の形、長さ 0 の線（平らなら描かない） | 1 |
| 1・0.5・0.25 画素の線（斜めを含む） | 1 |
| 破線（ずらし、`On` = 0 の丸い点、負のずらし、`Off` が太さより短い半透明の丸い破線） | 1 |
| 楕円の塗り、細長い楕円の太い線、太さの半分が半径を超える円、0.5 画素の線 | 1 |
| 縦横比 100:1 の楕円（横長と縦長、塗りと線）。ニュートン法の 5 回で収束する | 1 |
| 円弧（3 つの端の形、負の掃く角度、450 度、掃く角度 0、逆向きの破線、破線の円） | 1 |
| 扇形（半周より小さい・大きい・負の掃く角度） | 1 |
| 線・楕円の線・扇形のグラデーション（塗りの箱が設計のとおり） | 2 |
| グラデーションの文字（グレースケールと ClearType、半透明の色を含む） | 2 |

- **許容 2:** グラデーションのディザが 8 ビットの 1 段まで足すためである（R4a と同じ）
- **run の分かれ目:** 色のグリフとアトラスにまだ無いグリフが混ざったグラデーションの文字を `ResolveGlyphs` に通すと、割れた 3 つの run のどれもがブラシと箱を持った。色のグリフの文字の色の層は、ブラシの最初の色を不透明にした色でアトラスに頼まれた（`ResolveGlyphs_BrushedText_KeepsItsGradientOnEveryRun`）
- **定常状態:** 線・楕円・円弧・扇形のフレームと、グラデーションの文字のフレームは、どちらもアロケーション 0 で、表示リストも伸びなかった
- **テストで見つけて直したもの:**
  - 線と円弧の端の先の画素で、最後の破線を見落としていた
  - 破線の円の継ぎ目（始まり）の向こう側の破線を測っていなかった。また、継ぎ目で接する 2 本と破線の無い円に、継ぎ目で見えない端ができていた
  - 円弧の平らな端と四角い端は円の外へまっすぐ伸びるので、円の外では 1 つ前の破線の端のほうが近いことがある

## SVG と並べる（目での確認の前に）

`benchmarks/compare/curves.html` を Edge の headless で撮った（1.25 倍、600 × 420）。`XylemUI.E2E curves` を `text-capture` で撮った絵と、領域ごとに比べた（チャネルの差の最大）。

| 領域 | 中央値 | p95 | 最大 |
| --- | --- | --- | --- |
| 平らな端の線 | 0 | 1 | 1 |
| 丸い端の線 | 0 | 0 | 55 |
| 四角い端の線 | 0 | 1 | 52 |
| 斜めのグラデーションの線 | 0 | 1 | 33 |
| 1 画素の線 | 0 | 27 | 27 |
| 0.5 画素の線 | 0 | 1 | 40 |
| 破線 | 0 | 1 | 52 |
| 点線 | 0 | 11 | 39 |
| 楕円の塗り | 0 | 0 | 46 |
| 楕円の線 | 0 | 1 | 56 |
| 破線の円 | 0 | 4 | 124 |
| 放射のグラデーションの円 | 0 | 1 | 47 |
| 丸い端の円弧 | 0 | 1 | 59 |
| 反時計回りの四角い端の円弧 | 0 | 0 | 50 |
| 扇形 | 0 | 0 | 31 |
| 半透明の破線の円 | 0 | 0 | 31 |

- **最大の差:** 破線の円のほかは、形の縁の数画素の、縁のぼかし方の違いである
- **1 画素の線:** 線は 43.125〜44.375 画素にある。XylemUI は覆う面積どおりに、行 43 を 0.875、行 44 を 0.375 だけ塗る（G が 86 と 176。計算した値と同じ）。Edge は 109 と 153 で、二つの行に寄せて塗る
- **破線の円:** 破線の端の角度を円周に沿って比べると、XylemUI の端は弧の長さ（角度 × 半径）どおりの間隔で並ぶ。Edge は、円の後半の一部の端だけが最大 0.8 px ずれていた。Edge が描く Skia は、破線を `SkPathMeasure` で測る（`src/utils/SkDashPath.cpp` 338・391 行目）。その `SkContourMeasure` は、円弧（円錐曲線）を、中点が弦から 0.5 ÷ 倍率 px 以内になるまで分け、弦の長さを足して長さとする（`src/core/SkContourMeasure.cpp` 147・196・252〜276 行目）。端の位置は弧の長さでなく、この折れ線の長さで決まる。0.8 px という大きさがここから出ることまでは確かめていない
- **円弧のグラデーション:** SVG に円錐のグラデーションは無いので、比べの場面の円弧は、下から上への線形のグラデーションにした。円錐のグラデーションは R4a で確かめている

## 費用（main c18896b と、A・B・B・A の順で 3 回ずつ、中央値）

| | main | R4b |
| --- | --- | --- |
| `frames` の表示リストの段 | 29.1〜30.5 µs | 27.8〜30.5 µs |
| `frames` の Draw の段 | 29.4〜32.0 µs | 28.5〜31.8 µs |
| `frames` の GPU | 113.7〜114.7 µs | 112.6〜113.7 µs |
| `frames --shapes` の表示リストの段 | 67.3〜69.5 µs | 66.1〜67.6 µs |
| `frames --shapes` の GPU | 1,101.8〜1,102.8 µs | 1,101.8〜1,102.8 µs |
| `fill-rect`（1 個） | 7.39〜7.53 ns | 7.40〜7.49 ns |
| `draw-text`（1 グリフ） | 47.3〜48.3 ns | 45.5〜46.3 ns |

- **今の場面と R4a の形の場面:** 範囲が重なる。矩形とグリフの画素シェーダは、main と同じである
- **`draw-text`:** 2 ns 速く出た。色の `DrawText` は、塗りの番号を足した内部の版を呼ぶ形に変わり、機械語が変わった（351 命令から 358 命令。`dumpbin /disasm` で比べた）。速くするための変更ではないので、速くなったとは書かない
- **`frames --curves`（線・楕円・円弧を 1,000 個ずつ、グラデーションの文字 1,000 グリフ）:** 表示リストの段は 139.0〜145.1 µs、Draw の段は 106.7〜110.8 µs、GPU は 1,049.6 µs だった（3 回）。描く回数は 4 で、画素シェーダの種類が変わる所で分かれる

### レンダラの形の候補（main と交互に、`frames` と `frames --shapes` は 3 回ずつ）

| 形 | `frames` の GPU | `frames --shapes` の GPU | `frames --curves` の GPU | `--shapes` の表示リストの段 |
| --- | --- | --- | --- | --- |
| main | 112.6〜114.7 µs | 1,101.8〜1,102.8 µs | — | 67.3〜69.5 µs |
| 線・楕円・円弧を矩形のシェーダの種類に足し、値を `ShapeRecord` に入れる | 115.7〜117.8 µs | 1,138.7〜1,140.7 µs | 1,073.2 µs | 70.6〜72.7 µs |
| 線・楕円・円弧のシェーダを分け、値を `CurveRecord` に入れる（採った形） | 112.6〜113.7 µs | 1,101.8〜1,102.8 µs | 1,049.6 µs | 66.1〜67.6 µs |

- **シェーダ:** 矩形のシェーダに入れると、線・楕円・円弧を描かない場面まで遅くなった。R4a と同じく、シェーダに入ったコードの分だけ、すべての画素が遅くなる。分けると main と同じになり、線・楕円・円弧の場面も 23 µs 速くなった
- **記録:** `ShapeRecord` に線の値を足すと、R4a の形を書くたびに大きな記録を消して書くので、表示リストの段が約 3 µs 延びた
- **グラデーションの文字:** 最初から別のシェーダにした。グリフのシェーダに入れる版は、上の線・楕円・円弧と同じ理由で遅くなると見て、作っていない。描く回数は、グラデーションの文字の始まりと終わりで増える
