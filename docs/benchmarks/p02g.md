行 P02g（設計書 §4.4.1「P02g で入れる形」）を 2 つの PR に分けて入れる。Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、プロセスを 1 つのコアに固定して（`start /b /wait /affinity 4 /high`）測った。比べる main は、PR の merge-base を `.dev/` の worktree で publish した。main と PR は、A・B・B・A・B・A・A・B の順で各 4 回流した。値は各回の中央値（p50）の範囲である。

## 1 つ目の PR: `AccessibilityInfo` の API・a11y の木・部品の既定の役（Issue #627）

main は 2876b65。`a11y`・`frames --tree`・`input` は PR の af59858 で、`layout`・`todo`・`menu`・`tooltip`・`select` は 5c05144 で測った。2 つの違いは、`UiTree` の a11y の表を 1 つの物にまとめたこと（下）だけである。

### 木がある窓の a11y の段（`a11y`）

`a11y` の場面は、文字を持つボタン 1,000 個の列を、GPU の無い木で layout し、a11y の木を作る（最初の `WM_GETOBJECT` に当たる）。その後の 1 フレームで、真ん中のボタンの文字を変え、変更・layout の pass・a11y の段を分けて測る。変化の無いフレームの a11y の段と、最初のボタンの色だけを変えた（ホバーの見た目に当たる）後の a11y の段も測る。文字の葉は、Todo の場面と同じく DirectWrite のフォントで測る。この PR だけで 4 回流した。

| `a11y` の値 | この PR |
| --- | --- |
| 木を作る（`Start`、1,001 節） | 332〜443 µs |
| 文字の変更 | 0.2 µs |
| layout の pass | 3.6〜4.0 µs |
| a11y の段（直した節 1 つ） | 0.3〜0.4 µs |
| 変化の無いフレームの a11y の段 | 0.0 µs |
| 色だけを変えた後の a11y の段 | 0.0 µs |

- 文字の葉の変更は、その葉に印を付ける。a11y の段は、印のノードと、その親のそれぞれについて、役を持つ最も近いノードの節を直す。この場面では、どちらもそのボタンの節なので、直す節は 1 つで、窓の節とほかの 999 個のボタンの節には触れない。ボタンの名前は文字の葉からたたむので、名前が変わる
- 色だけの変化は印を付けない。最初の実装では、ホバーの色の変化も印を付け、親の側の節（ボタンの親が役の無い列なら窓の節）を直していた。窓の節を直すと、その子の全部を歩いて矩形を求め直すので、木の大きさに比例する。今は、印を付けるのは layout・文字・a11y の段に及ぶ変化だけで、疑似状態（Disabled・Focused・Open）のような自分の節の中だけの変化は、自分の節だけを直す（`AccessibilityTests.OwnState_MakesAgainTheNodeAlone`、フォーカスの移動で直す節は 1 つ）
- 変化の無いフレームの割り当ては 0 である（`AccessibilityTests.SteadyState_FocusAndHoverWithTheTree_AllocatesNothing`、木のある窓でフォーカスとホバーを 2 つのボタンの間で動かす）

### 木の無い窓（main と比べる）

### `UiTree` の a11y の表を 1 つの物にまとめた

5c05144 では、`UiTree` が a11y の表を 5 つの欄（辞書 3 つ、`HashSet` 1 つ、木）で持っていた。その形では、`input` の選択の範囲のフレームが main より 2〜4 % 長く、範囲が重ならなかった（1,000 個の葉を描き直すフレーム 441〜452 µs → 454〜458 µs、50 個の葉のドラッグ 375〜377 µs → 380〜387 µs）。この場面は a11y の木を作らず、どの段も a11y のコードを通らない。

- 印を付ける所と a11y の段の呼び出しを全部外した写しを作って測ると、遅いままだった（描き直すフレーム 456〜459 µs）。違いは印の確かめではない
- 5 つの欄を 1 つの物に移した写しでは、ドラッグが main と同じ 369〜379 µs になり、描き直すフレームも 444〜456 µs に近づいた。欄が増えると、`UiTree` のほかの欄の並びが変わる（参照の欄はまとめて置かれる）。描く段は葉ごとに `UiTree` の欄を読むので、その置き場所の違いが出たと考える
- af59858 で、5 つの欄を 1 つの物（`AccessibilityTables`）にまとめた。上の表の `input` の値は、その形のもので、選択の範囲の 3 つの値は main と範囲が重なる
