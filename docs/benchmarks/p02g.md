行 P02g（設計書 §4.4.1「P02g で入れる形」）を 2 つの PR に分けて入れる。Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、プロセスを 1 つのコアに固定して（`start /b /wait /affinity 4 /high`）測った。比べる main は、PR の merge-base を `.dev/` の worktree で publish した。main と PR は、A・B・B・A・B・A・A・B の順で各 4 回流した。値は各回の中央値（p50）の範囲である。

## 1 つ目の PR: `AccessibilityInfo` の API・a11y の木・部品の既定の役（Issue #627）

main は 51834bf。

### 木がある窓の a11y の段（`a11y`）

`a11y` の場面は、文字を持つボタン 1,000 個の列を、GPU の無い木で layout し、a11y の木を作る（最初の `WM_GETOBJECT` に当たる）。その後の 1 フレームで、真ん中のボタンの文字を変え、変更・layout の pass・a11y の段を分けて測る。変化の無いフレームの a11y の段も測る。文字の葉は、Todo の場面と同じく DirectWrite のフォントで測る。この PR だけで 4 回流した。

| `a11y` の値 | この PR |
| --- | --- |
| 木を作る（`Start`、1,001 節） | 354〜380 µs |
| 文字の変更 | 0.2 µs |
| layout の pass | 3.9〜4.0 µs |
| a11y の段（直した節 1 つ） | 0.3 µs |
| 変化の無いフレームの a11y の段 | 0.0 µs（p95 0.1 µs） |

- 文字の葉の変更は、その葉に印を付ける。a11y の段は、印のノードと、その親のそれぞれについて、役を持つ最も近いノードの節を直す。この場面では、どちらもそのボタンの節なので、直す節は 1 つで、窓の節とほかの 999 個のボタンの節には触れない。ボタンの名前は文字の葉からたたむので、名前が変わる
- 変化の無いフレームの割り当ては 0 である（`AccessibilityTests.SteadyState_HoverWithTheTree_AllocatesNothing`、木のある窓でホバーを動かす）

### 木の無い窓（main と比べる）

木の無い窓では、印を付ける所（`Invalidation.Invalidate` と `MarkDirty` の入口、`OnRectChanged`、疑似状態、`SetFocusable`）が bool を 1 つ見るだけで、a11y の段はすぐ戻る。

- `frames --tree` は、1 回目の 8 回（A・B・B・A・B・A・A・B）の中ほどの 4 回が、main もこの PR も遅い状態（CPU の 1 フレーム 0.156〜0.172 ms）で走った。順を逆にして流し直した 8 回（上の表）は、この PR の最初の 1 回（0.129 ms）のほかは 0.116〜0.117 ms で重なった
