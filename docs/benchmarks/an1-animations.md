# AN1: アニメーション

アニメーションの時計、`Animation`、ペイントの値の `Transition`、`Show` の出入りを入れた（ロードマップの行 AN1、Issue #475、設計書 §2.14）。動いているアニメーションがフレームにどれだけ時間を足すかと、main（2c8f333）の一覧の場面への影響を測った。どれも Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、プロセスを 1 つのコアに固定して（`start /affinity 4 /high`）測った。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
<dir>/XylemUI.E2E.exe animations   # アニメーションの費用。GPU もウィンドウも使わない
<dir>/XylemUI.E2E.exe lists        # 1 万行の For と Show（V3a の場面）
```

## アニメーションの費用（`animations`、3 回）

`animations` の場面は、1,000 個の箱を並べた列を持つ。先頭の N 個は、不透明度をそれぞれ自分の `Animation` に結ぶ。標本ごとに時計を 16 ms 進めてフレームを 1 回走らせ、アニメーションの一覧を進める時間（結んだ値の effect もここで走る）と、フレーム全体の時間を取る。値は 201 標本の中央値。

| 動いているアニメーション | 一覧を進める時間 | フレーム |
| --- | --- | --- |
| 0 | 0 µs | 0 µs（フレームを要求しない） |
| 1 | 0.1〜0.2 µs | 24〜27 µs |
| 100 | 7.1〜9.3 µs | 35〜39 µs |
| 1,000 | 92〜95 µs | 146〜156 µs |

一覧を進める時間は、アニメーション 1 つあたり約 0.09 µs で、数に比例する。動いているアニメーションが無ければ、時計はフレームを要求しないので、何もしない窓はフレームを走らせない（設計書 §2.14「フレームの時計」）。

1 つの箱の幅をアニメーションに結んだ場面では、一覧を進める時間が 0.5〜0.6 µs、レイアウトの pass が 66〜70 µs、フレームが 89〜95 µs だった。外から動かすアニメーションは layout のプロパティにも結べ、そのときは毎フレーム layout をやり直す（設計書 §2.14「動かせるプロパティ」）。この場面では、毎フレーム 1,000 個の列を並べ直した。

### 割り当て

動いているアニメーションと遷移を毎フレーム進める定常状態では、フレームは 0 バイトだった（`AnimationTests.SteadyState_RunningAnimationAndTransition_AllocatesNothing`）。

## main（2c8f333）への影響（`lists`、各 6 回、交互に）

| 変更 | 差分 main | 差分 AN1 | 描画の段 main | 描画の段 AN1 |
| --- | --- | --- | --- | --- |
| 末尾に 1 行足す | 105.9 µs | 111.7 µs | 529 µs | 551 µs |
| 真ん中の 1 行を外す | 97.0 µs | 107.1 µs | 548 µs | 580 µs |
| 順を逆にする | 853.8 µs | 848.5 µs | 569 µs | 591 µs |
| 真ん中の 1 行の値を変える | 78.9 µs | 85.8 µs | 327 µs | 328 µs |

値は各回の中央値の中央値。`Show` の条件を 1 回変える時間は、どちらも 1.6 µs だった。描画の段の差は、回ごとの幅（main で 502〜556 µs、AN1 で 521〜595 µs）の中に収まる。

### 差分が 5〜10 µs 遅い理由

1 行の変更の差分が 5〜10 µs 遅くなったのは、AN1 の仕事ではなく、変わっていない差分のコードが置かれた番地による。

1 行の値の変更で走る effect は、`For` の 1 つと、変えた行の背景の 1 つだけである。AN1 は `Effect.RunQueued` に一時停止の確認（`Scope.PausedCount > 0`、一時停止したスコープが無ければ 0）を足した。この確認が 2 回で 7 µs かかることはない。

確認を外した作業用の版（コミットしていない）と比べた。値の変更の差分は、main が 86.9 µs、確認を外した版が 86.9 µs、AN1 が 93.1〜93.7 µs だった（各 6〜8 回、交互に）。三つの実行ファイルを逆アセンブルすると、差分の本体 `ForBlock<T, TKey>.Reconcile` の機械語はどれも同じ 0x1270 バイトだった。違ったのは、置かれた番地だけである。

| 版 | 値の変更の差分 | `Reconcile` の先頭（64 で割った余り） | `Keep` の先頭（64 で割った余り） |
| --- | --- | --- | --- |
| main | 86.9 µs | 32 | 16 |
| 確認を外した版 | 86.9 µs | 32 | 16 |
| AN1 | 93.1〜93.7 µs | 0 | 48 |

速い二つの版は同じ番地の並びを持ち、遅い版だけが違う。AN1 の行の番地は、確認の数え上げを静的初期化を持たない別のクラスの欄に移した作業用の版で読んだ。この版も 93.1 µs で、`Scope.PausedCount` のままの AN1（93.7 µs）と変わらなかったので、採らなかった。
