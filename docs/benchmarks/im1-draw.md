# IM1 1b-1: 画像の描画の経路

行 IM1 の 1b-1（Issue #749、設計書 §5.0.4「持ち主と寿命」「レンダラへの渡し方」「テクスチャ」）。窓の画像の表 `TextureCache`、世代付きのハンドル `ImageHandle`、表示リストの命令 `Image`、D3D11 の画像ごとのテクスチャ（`GenerateMips` で mipmap を作る）と trilinear で読むシェーダを足した。Windows 11 26300、Intel Core i5-13400F、NVIDIA GeForce RTX 3060 Ti、60 Hz のモニタ、NativeAOT の Release（win-x64）。main は `de0584c`。

## 再現

```powershell
./vendor/build.ps1
$env:PATH += ';C:\Program Files (x86)\Microsoft Visual Studio\Installer'
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
<dir>/XylemUI.E2E.exe frames 600 [--shapes | --curves | --groups | --scopes rounded | --images]
<dir>/XylemUI.E2E.exe startup 10
<dir>/XylemUI.E2E.exe image-upload 20
```

`frames` の場面は、main とこの PR を場面ごとに交互に流し、それを 3 回くり返した。値は 3 回の各回の中央値（p50）の中央値。

## 今ある場面

Draw の段は、アトラスのアップロード・インスタンスの書き込み・描画の命令の発行の CPU 時間。

| 場面 | Build（main） | Build（PR） | Draw（main） | Draw（PR） | GPU（main） | GPU（PR） |
| --- | --- | --- | --- | --- | --- | --- |
| plain | 18.3 µs | 22.4 µs | 23.1 µs | 28.6 µs | 73.7 µs | 73.7 µs |
| `--shapes` | 59.4 µs | 57.9 µs | 70.9 µs | 72.0 µs | 736.3 µs | 735.2 µs |
| `--curves` | 118.5 µs | 120.1 µs | 105.2 µs | 106.3 µs | 673.8 µs | 673.8 µs |
| `--groups` | 27.1 µs | 26.3 µs | 47.2 µs | 44.5 µs | 594.9 µs | 591.9 µs |
| `--scopes rounded` | 33.1 µs | 30.8 µs | 32.1 µs | 29.7 µs | 121.9 µs | 120.8 µs |

- plain の Draw が 5.5 µs 長く出たが、同じ流しの Build の段も 4.1 µs 長い。Build の段のコード（`DisplayList.FillRect` と `Scene.Build`）は、この PR で変えていない。同じ PR の 1 つ前の publish では、plain は PR の方が短かった（Build 24.0 µs 対 27.2 µs、Draw 27.0 µs 対 29.4 µs）。実行されるコードは変わらず、publish ごとに向きが変わるので、`p02d3.md` に記録したのと同じ、コードの配置の差と読む
- `--shapes` は、1 つ前の publish で Draw が main より長かった（9 回の中央値で 84.0 µs 対 80.0 µs）。そのときは、画像の命令の処理を `WriteInstances` の繰り返しの中に書いていた。インライン化しないメソッド（`WriteImage`）に出すと、6 回ずつで 75.3 µs 対 74.0 µs になり、この表でも差は 1.1 µs で、各回の幅（70.4〜78.3 µs）の中にある。命令の種類を見分ける比べ方は、図形の命令では変わらないので、繰り返しの中のコードが増えたことで、ほかの命令の処理が遅くなったと読む（命令の数やサイクルは数えていない）
- 曲線の命令は、グループのないリストで、画像の命令と見分けるために比べる回数が 1 回増えた。`--curves` の Draw は 1.1 µs の差で、各回の幅の中にある

## 画像の場面

`frames --images`: 1,000 個の四角を、100 枚の 64 × 64 の画像（不透明）から、16 × 16 の論理ピクセルで描く。1 枚の画像が 10 個続くので、描画の命令は 100 回に分かれる（マーカーとテキストを足して 102 回）。plain の場面と同じ配置で、四角の代わりに画像を描く。

| | Build | Draw | GPU | 描画の命令 |
| --- | --- | --- | --- | --- |
| plain（PR） | 22.4 µs | 28.6 µs | 73.7 µs | 2 回 |
| `--images` | 33.2 µs | 62.3 µs | 110.6 µs | 102 回 |

Draw の段は 33.7 µs 長い。画像ごとにテクスチャを結び直して描画を分けるためで、1 回あたり約 0.34 µs。GPU は 36.9 µs 長い。Build の段の 10.8 µs は、画像の命令が四角の命令より大きな記録（ハンドルと元の範囲）を持つ分。

## アップロード

`image-upload 20`: 正方形の画像 1 枚を表に入れ、マーカーだけのフレームで描く。Draw の段がアップロードする（`UpdateSubresource` と `GenerateMips`）。描画の直後に画素を 1 つ読み戻すと、CPU は GPU の仕事が終わるまで待つ。Draw の始めからそこまでを「GPU が終わるまで」とした。何もアップロードしないフレームを同じ方法で測ると 0.19 ms（p50、100 回）で、それを引いた値をアップロードの分とする。

| 一辺 | 画素のバイト数 | Draw の CPU（p50） | GPU が終わるまで（p50） | アップロードの分 |
| --- | --- | --- | --- | --- |
| 64 px | 16 KB | 0.02 ms | 0.23 ms | 0.04 ms |
| 256 px | 256 KB | 0.03 ms | 0.24 ms | 0.06 ms |
| 1,024 px | 4 MB | 0.14 ms | 0.55 ms | 0.36 ms |
| 2,048 px | 16 MB | 0.97 ms | 2.09 ms | 1.90 ms |
| 4,096 px | 64 MB | 4.76 ms | 8.52 ms | 8.33 ms |

- 1,024 px までは、1 枚のアップロードがフレームの予算（§11.3）の中に収まる。4,096 px の 1 枚は、Draw の CPU だけで 4.8 ms かかり、GPU が終わるまで 8.5 ms かかる。アプリは目標の大きさを指定してデコードできるが、指定が無ければ元の大きさでデコードする（設計書 §5.0.4「デコードの大きさ」）。指定の無い大きな写真は、最初に描くフレームでこの時間がかかる。キャッシュの上限と合わせて、3 つ目の PR の 100 枚の画像の場面で見る
- 最初の測り方は、GPU のタイムスタンプ（`GpuFrameTimer`）だった。中央値が大きさの順に並ばなかった（1,024 px 0.24 ms が 256 px 0.25 ms より短い、4,096 px 4.7 ms が 2,048 px 6.9 ms より短い）ので使わなかった。タイムスタンプがアップロードの写しのどこまでを含むかは、ドライバによる

## 起動と大きさ

| | main | この PR |
| --- | --- | --- |
| 起動から最初のフレームの表示まで（`startup 10`、p50） | 742.0 ms | 734.6 ms |
| `XylemUI.E2E.exe` | 7,150,080 バイト | 7,173,120 バイト（+23,040） |

画像の画素のシェーダは、変換の中の命令のシェーダと同じく、レンダラを作るときにスレッドで作る（最初に画像を描くフレームが待つ）。起動の時間は延びていない。trim と AOT の警告は 0。

## テスト

- `tests/XylemUI.Rendering.D3D11.Tests` の `ImageRenderTests`（WARP）: 1 対 1 で画素のとおり（半透明の画素を含めて各チャンネル 1 以内）、4 分の 1 に縮めた市松模様が灰色（125〜130、mipmap を作らない形では白と黒になって失敗することを確かめた）、元の範囲で切り取った部分だけ（端も隣の部分の色を取らない。範囲を無視する形で失敗することを確かめた）、不透明度の群（層と、子に配る形）・角丸の切り抜き・90 度の回転の中、`Release` した枠に入れた別の画像、捨てたハンドルを描くと不変条件の違反、画像を描く定常状態のフレーム 100 回でアロケーションが 0
- `tests/XylemUI.Core.Tests` の `TextureCacheTests` と `ImageListTests`: 世代と 2 つの待ち行列（レンダラが無くても枠ごとに 1 つ）、引数の確かめ、四角を画素に合わせる、群と変換の中の書き方、`Reset` の後に配列が増えない。`WindowFramesTests` で、フレームが木の `TextureCache` をレンダラに渡す
- `tests/XylemUI.Text.Tests` の `ResolveGlyphsTests`: グリフをそろえて書き直したリストに画像が残る
