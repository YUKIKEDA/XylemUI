# I1a: タッチとペンを WM_POINTER で受ける

タッチとペンを `WM_POINTER` で受け、ポインタごとの番号・キャプチャ・押下・ホバー、ペンの値、途中の点、タッチのタップを入れた（ロードマップの行 I1 の I1a、Issue #388、設計書 §7「タッチとペン」）。どれも Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、性能コア（論理プロセッサ 2）に固定し、優先度を高くして測った。比べた main は、ブランチの土台の d7765df である。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
cmd /c start "" /affinity 4 /high /wait /b <dir>\XylemUI.E2E.exe input
```

`input` の場面は、ウィンドウを開かない。I1a で次の 3 つを足した。

- **ペンの move:** マウスの move と同じ深さ 1 と 50 の箱の鎖を、番号 1 のペンが動く（`us_per_pen_move_depth_*`）
- **タッチのタップ:** 最初の葉の上で、番号 1 のタッチが下り、上がり（Click が 1 つ）、離れる（`us_per_touch_tap`）
- **途中の点:** ペンの move が 8 点をまとめて運び、最初の葉のハンドラが `GetIntermediatePoints()` で読む（`us_per_pen_move_8_points`）

## タッチとペン（I1a の 4 回、21 標本の中央値）

| 指標 | I1a | 比べるマウスの指標（I1a） |
| --- | --- | --- |
| ペンの move、深さ 1 | 0.156〜0.167 µs | move、深さ 1: 0.145〜0.170 µs |
| ペンの move、深さ 50 | 4.40〜4.85 µs | move、深さ 50: 4.35〜5.00 µs |
| タッチのタップ（下りる・上がる・離れる） | 0.283〜0.304 µs | クリック（押す・離す）: 0.313〜0.343 µs |
| ペンの move、途中の点 8 つを読む | 0.180〜0.182 µs | — |

- ペンの move は、マウスの move と範囲が重なる
- タッチのタップは、メッセージが 1 つ多いのにマウスのクリックより短い。タッチはホバーを持たないので、ホバーの判定（祖先の鎖を作って前と比べる）と、カーソルを選ぶことをしない
- 途中の点 8 つを読むと、深さ 1 のペンの move より 0.02 µs 長い。1 つのメッセージで初めて読むときに、プラットフォームから 8 点を写し、古い順に並べ替えて論理ピクセルに直す

## マウスと鍵盤（main と交互に 4 回、21 標本の中央値）

| 指標 | main | I1a |
| --- | --- | --- |
| move、深さ 1 | 0.146〜0.171 µs | 0.145〜0.170 µs |
| move、深さ 50 | 5.05〜5.89 µs | 4.35〜5.00 µs |
| ホバーが変わる move | 0.188〜0.227 µs | 0.189〜0.208 µs |
| クリック | 0.303〜0.384 µs | 0.313〜0.343 µs |
| クリック（scoped） | 0.298〜0.331 µs | 0.321〜0.346 µs |
| ホイール | 0.081〜0.090 µs | 0.092〜0.094 µs |
| キー、深さ 50 | 1.75〜1.87 µs | 1.69〜2.20 µs |
| スクロールするキー | 0.092〜0.112 µs | 0.084〜0.090 µs |
| Tab（10,101 ノード） | 166〜209 µs | 161〜180 µs |

- ホイールのほかは、範囲が重なる
- **ホイール:** 最後の版を測った 2 つの回で、どちらも I1a が main より長かった。上の表の回は main 0.081〜0.090 µs・I1a 0.092〜0.094 µs、次の回（下の一時の版と交互に 3 回）は main 0.081〜0.089 µs・I1a 0.105 µs である。ホイールの `Route` と `Scroll` は main と同じコードで、増えたのはポインタの状態を引く手間である。配送の番号を付けること、番号からポインタの状態を引くこと、ホバーの判定とカーソルを選ぶことがその状態のオブジェクトを通して読むこと
  - 大きくなった `PointerInput`（main の約 48 バイトから約 80 バイト）を、ホイールのたびにポインタの状態に写す。これを止めた一時の版も 0.102〜0.103 µs（3 回のうち 1 回は 0.189 µs）で、I1a（同じ回 0.105 µs）と変わらなかったので、写すことは原因ではない
  - 同じ I1a の版が、回によって 0.092 µs と 0.105 µs に動いた。main も 0.080〜0.092 µs の幅がある。命令の数で分けるには、管理者で動かす VTune が要る（`docs/benchmarks/l8-counters.md`）
- 1 回目の計測では、ホイールのほかに 3 つが重ならなかった。どれも直して、上の表（3 回目）では重なる
  - **ホバーを待っていた判定:** ホイールと move のたびに、ポインタの配列を回して保留の印を消していた。保留があるときだけ回す別の関数にした（`TestPendingHovers`）。2 回目で、ホイールは 0.105 µs から 0.093〜0.105 µs になった
  - **クリックとホバーの変化:** 押下とホバーを外すノードごとに、ほかのポインタがそのノードを持っていないかを確かめていた（`HeldByAnother`）。いるポインタが 1 つのときは確かめないようにした。2 回目にクリック（scoped）は main 0.293〜0.300 µs に対して 0.321〜0.350 µs で、3 回目に重なった
  - **スクロールするキー:** 1 回目は main 0.083〜0.085 µs に対して 0.091〜0.097 µs だった。キーの経路は I1a で変えていない。2 回目からは重なった
- move、深さ 50 は、どの回でも I1a のほうが短かった（1 回目 main 4.90〜5.41 µs・I1a 4.37〜5.21 µs、2 回目 4.87〜4.96 µs・4.33〜4.66 µs）。ハンドラ 100 個の呼び出しのコードは変えておらず、理由は分けていない

## 割り当て

- Core: タッチ 2 つのタップ、途中の点 8 つを読むペンの move、そのフレームを 1,000 回して 0 バイト（`TouchPenInputTests.SteadyState_TouchesAndPen_AllocateNothing`）
- Windows: タッチの `WM_POINTERDOWN`・`UPDATE`・`UP`・`LEAVE` と、ペンの `UPDATE`（履歴 8 つを読む）・`LEAVE` を 1,000 回送って 0 バイト（`Win32WindowTouchPenTests.Delivery_TouchAndPen_AllocatesNothing`）
