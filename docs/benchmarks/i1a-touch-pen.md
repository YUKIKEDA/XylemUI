# I1a: タッチとペンを WM_POINTER で受ける

タッチとペンを `WM_POINTER` で受け、ポインタごとの番号・キャプチャ・押下・ホバー、ペンの値、途中の点、タッチのタップを入れた（ロードマップの行 I1 の I1a、Issue #388、設計書 §7「タッチとペン」）。どれも Windows 11 26300、Intel Core i5-13400F、NativeAOT の Release で、性能コア（論理プロセッサ 2）に固定し、優先度を高くして測った。比べた main は、ブランチの土台の d7765df である。

## 再現

```powershell
dotnet publish benchmarks/XylemUI.E2E -c Release -r win-x64 -o <dir>
cmd /c start "" /affinity 4 /high /wait /b <dir>\XylemUI.E2E.exe input
```

`input` の場面は、ウィンドウを開かない。I1a で次の 3 つを足した。

- **ペンの move:** マウスの move と同じ深さ 1 と 50 の箱の鎖を、番号 1 のペンが動く（`us_per_pen_move_depth_*`）
- **タッチのタップ:** 最初の葉の上で、番号 1 のタッチが下り、上がり（Click が 1 つ）、離れる（`us_per_touch_tap`）
- **途中の点:** ペンの move が 8 点をまとめて運び、最初の葉のハンドラが `GetIntermediatePoints()` で読む（`us_per_pen_move_8_points`）

## タッチとペン（最後の版、4 回、21 標本の中央値）

| 指標 | I1a | 比べるマウスの指標（I1a） |
| --- | --- | --- |
| ペンの move、深さ 1 | 0.146〜0.156 µs | move、深さ 1: 0.143〜0.159 µs |
| ペンの move、深さ 50 | 4.30〜4.58 µs | move、深さ 50: 4.31〜4.48 µs |
| タッチのタップ（下りる・上がる・離れる） | 0.279〜0.305 µs | クリック（押す・離す）: 0.309〜0.318 µs |
| ペンの move、途中の点 8 つを読む | 0.180〜0.196 µs | — |

- ペンの move は、マウスの move と範囲が重なる
- タッチのタップは、メッセージが 1 つ多いのにマウスのクリックより短い。タッチはホバーを持たないので、ホバーの判定（祖先の鎖を作って前と比べる）と、カーソルを選ぶことをしない
- 途中の点 8 つを読むと、深さ 1 のペンの move より 0.03 µs 長い。1 つのメッセージで初めて読むときに、プラットフォームから 8 点を写し、古い順に並べ替えて論理ピクセルに直す

## マウスとキー（最後の版、main と交互に 4 回、21 標本の中央値）

| 指標 | main | I1a |
| --- | --- | --- |
| move、深さ 1 | 0.146〜0.172 µs | 0.143〜0.159 µs |
| move、深さ 50 | 4.96〜5.58 µs | 4.31〜4.48 µs |
| ホバーが変わる move | 0.189〜0.219 µs | 0.187〜0.205 µs |
| クリック | 0.297〜0.324 µs | 0.309〜0.318 µs |
| クリック（scoped） | 0.302〜0.326 µs | 0.321〜0.346 µs |
| ホイール | 0.081〜0.082 µs | 0.093〜0.095 µs |
| キー、深さ 50 | 1.71〜1.81 µs | 1.71〜1.81 µs |
| スクロールするキー | 0.084〜0.093 µs | 0.084〜0.085 µs |
| Tab（10,101 ノード） | 165〜172 µs | 163〜171 µs |

- ホイールのほかは、範囲が重なる
- **ホイールは、I1a のほうが 1 回 0.011〜0.014 µs 長い。** ホイールの `Route` と `Scroll` は main と同じコードで、増えたのはポインタの状態を引く手間である。配送の番号を付けること、番号からポインタの状態を引くこと、ホバーの判定とカーソルを選ぶことがその状態のオブジェクトを通して読むこと
- move、深さ 50 は、どの回でも I1a のほうが短かった。ハンドラ 100 個の呼び出しのコードは変えておらず、理由は分けていない

## 命令とサイクルの数（VTune）

ホイールと move を 1,000,000 回と 5,000,000 回送り、差を 4,000,000 で割った（`benchmarks/counters/instructions.ps1 -Command input-loop`、`benchmarks/XylemUI.E2E/InputLoop.cs`）。main と I1a を A・B・B・A の順で 2 巡し、性能コアに固定した。`InputLoop.cs` は V1c の API だけで書いたので、main にも同じファイルを入れて測った。葉に move のハンドラがあり、ホイールは `input` の場面より長い。

| | main | `PointerInput` が 80 バイトの版 | 最後の版（64 バイト） |
| --- | --- | --- | --- |
| ホイールの命令 | 3,032〜3,033 | 3,277（+8.0 %） | 3,179（+4.9 %） |
| ホイールのサイクル | 808〜818 | 860（+6.4 %） | 845（+3.3 %） |
| move の命令 | 2,219〜2,220 | 2,487（+12.0 %） | 2,388（+7.6 %） |
| move のサイクル | 652〜671 | 698（+4.1 %） | 665（+2.0 %） |

- 中央値である。main は、2 つの版それぞれと交互に測った 2 回の値
- 80 バイトの版では、関数ごとに分けた命令の中に `SpanHelpers.Memmove` がホイール 1 回あたり約 290 命令あり、main には無かった。`PointerInput` を値で写すのは、ポインタの状態に最後の入力を残す 1 か所（`pointer.Last = input`）だけである。宣言の順では 1 バイトの値と 4 バイトの値が交互に並び、詰め物で 80 バイトになっていた。NativeAOT は、この大きさの写しを `Memmove` の呼び出しにする
  - `[StructLayout(LayoutKind.Auto)]` で並べ方を実行環境に任せると、64 バイト以下になった。上限は `WindowInputTests.Sizes_NodeAndLooks_StayWithinTheirBounds` で確かめる。`Memmove` は 1 回あたり 8 命令（main）と 16 命令になった
  - 時間を測るだけの前の調べでは、写すことを止めた一時の版が I1a と変わらなかった（0.102〜0.103 µs と 0.105 µs）。その回は同じ版でも 0.092〜0.105 µs と動いたので、この差は見分けられなかった
- 残りの差は、ホイールで約 150 命令、約 30 サイクルである。関数ごとに分けると、同じ数が回ごとに別の関数に入るので（標本の取り方による）、どの手順がいくつかまでは分けられなかった。この中には、測る側が 1 回ごとに大きくなった `PointerInput` を作る分（`PointerInput..ctor` に約 50 命令）も入る
- `input` の場面のホイールは 1 回約 350 サイクルなので、同じ約 30〜50 サイクルが 0.011〜0.014 µs、15 % ほどになる

## 直した経緯

1 回目の計測では、ホイールのほかに 3 つが main と重ならなかった。

- **ホバーを待っていた判定:** ホイールと move のたびに、ポインタの配列を回して保留の印を消していた。保留があるときだけ回す別の関数にした（`TestPendingHovers`）。ホイールは 0.105〜0.108 µs から 0.093〜0.105 µs になった
- **クリックとホバーの変化:** 押下とホバーを外すノードごとに、ほかのポインタがそのノードを持っていないかを確かめていた（`HeldByAnother`）。いるポインタが 1 つのときは確かめないようにした。クリック（scoped）は、main 0.293〜0.300 µs に対して 0.321〜0.350 µs だったのが、範囲が重なった
- **スクロールするキー:** 1 回目は main 0.083〜0.085 µs に対して 0.091〜0.097 µs だった。キーの経路は I1a で変えていない。2 回目からは重なった
## 割り当て

- Core: タッチ 2 つのタップ、途中の点 8 つを読むペンの move、そのフレームを 1,000 回して 0 バイト（`TouchPenInputTests.SteadyState_TouchesAndPen_AllocateNothing`）
- Windows: タッチの `WM_POINTERDOWN`・`UPDATE`・`UP`・`LEAVE` と、ペンの `UPDATE`（履歴 8 つを読む）・`LEAVE` を 1,000 回送って 0 バイト（`Win32WindowTouchPenTests.Delivery_TouchAndPen_AllocatesNothing`）
